# 编辑器键位统一标准

一个人在编辑器里需要的操作是固定的，换编辑器不该换肌肉记忆。这份文档定一套跨编辑器的标准，
并记录每个编辑器离标准还差多远。

盘点的骨架来自《程序员修炼之道》20 周年版 Topic 18「Power Editing」——它列了一组
不该靠鼠标和菜单完成的能力，正好可以当作「一个编辑器至少要能干什么」的检查表。

> 范围说明：这些操作大多**不经过 Karabiner**，但同样属于「这台机器的键位」。
> 已登记进 `custom/apps.yml`，会出现在 `keymap.html` 和练习页里。

## 一、数据来源与可信度

**Zed 键位取自官方仓库，不是从二进制猜的。**

| 来源 | 作用 |
|---|---|
| [`assets/keymaps/default-macos.json`](https://github.com/zed-industries/zed/blob/main/assets/keymaps/default-macos.json) | 绝大多数绑定 |
| [`assets/keymaps/macos/vscode.json`](https://github.com/zed-industries/zed/blob/main/assets/keymaps/macos/vscode.json) | `settings.json` 里 `base_keymap: VSCode` 叠加的一层 |
| `~/.config/zed/keymap.json` | 自己改的，表里标「自定义」 |

**VSCode 那层只有约 20 条**，它没碰 `⌘D`、复制行、移动行、删除行——所以 Zed 基本可以当
macOS 默认看。（一度以为它会大改，是错的。）

以下两点**未经实证**，用到时请自行确认：
- **IntelliJ 的键位**是凭记忆写的，这台机器上没装，无法核对。
- **书里的清单是我用自己的话复述的**，没拿到逐字原文（O'Reilly 付费墙）。需要精确引用请翻实体书。

## 二、标准怎么定的

两条原则，按顺序适用：

**1. 行编辑块跟 JetBrains 现代 macOS 约定。**
这是从 JetBrains 带过来的肌肉记忆，值得保留——而且它比 VS Code / Zed 的出厂设定更自洽：

```
⌥↑ / ⌥↓     扩展 / 收缩选择      ← 「⌥ = 放大一级单位」，和 ⌥←→ 按词同一条原则
⌥⇧↑ / ⌥⇧↓   上移 / 下移一行
```

VS Code 和 Zed 出厂都是 `⌥↑↓` 移动行、`⌥⇧↑↓` 复制行，**两边都已改过来**。

> 历史注记：JetBrains 更早的 Mac keymap 用 `⌘W` / `⌘⇧W` 做扩展/收缩选择。
> 那套没被继承——`⌘W` 在 macOS 上是「关闭窗口」的通用约定，抢它代价太大。
> 现代 JetBrains macOS keymap 自己也换成了 `⌥↑↓`。

**2. 其余跟 VS Code / Zed 共识。**
这两家在注释、多光标、跳定义、大纲、重命名上几乎完全一致，而 IntelliJ 是那个离群的。
既然主力已经从 JetBrains 换成 Zed，就以多数派为准。

## 四、Hyper 层负责哪一段

书里 12 类能力，**只有第 1 类「按字符/词/行移动与选择」属于 Hyper 层的战场**，
而 Hyper 层几乎全部投入在这一类上。这不是失衡，是分工：

| | 归谁管 | 为什么 |
|---|---|---|
| 高频、要连按、手不能离开主键区 | **Hyper 层** | 移动光标一天几百次，`⇪H/L` 实测 87/90 次 |
| 单个 `⌘` 组合能覆盖 | **编辑器自己** | `⌘/`、`⌘Z`、`⌘D` 已经够近，Hyper 化没有收益 |
| 双修饰键 + 方向键 | **候选** | 如 `⌘⌥↑↓` 多光标——形状正是 Hyper 擅长消灭的 |

目前唯一明确划算的候选是**多光标 `⌘⌥↑↓`**：书里点名，形状难按，且 Zed / VS Code 一致。
