# 编辑功能全清单 · Zed 与 Hyper 层的覆盖评估

盘点「一个程序员在编辑器里到底需要哪些操作」，逐条对上三样东西：

1. 《程序员修炼之道》Topic 18「Power Editing」点名要练到不用鼠标的
2. 你 Zed 里**实际**的键位
3. Capslock 的 Hyper 层有没有覆盖

目的是判断哪些该进 Hyper 层、哪些留在应用里就好。

---

## 数据来源与可信度

**Zed 键位是抠出来的，不是猜的。** 你设了 `"base_keymap": "VSCode"`，所以实际生效的是三层叠加：

```
Zed 内置 default-macos  ←  VSCode 兼容层覆盖  ←  你的 ~/.config/zed/keymap.json
```

Zed 不落地默认 keymap 文件，只能从 app 二进制里抠。方法是定位一段连续可打印区，按 JSON 数组切开，用特征绑定认领身份：

| 数组 | 段数 | 是什么 | 认领依据 |
|---|---|---|---|
| #1 | 128 | `default-macos` | `cmd-backspace` → `DeleteToBeginningOfLine` |
| #13 | 21 | VSCode 兼容层（macOS） | `cmd-backspace` + `shift-alt-up/down` 行编辑 |
| #10 | 8 | JetBrains 兼容层 | `cmd-shift-d` + `ctrl-cmd-up/down` |

**按键级**（不是按动作级）做优先级合并——一个动作在低层的绑定，可能因为高层抢走了那个键而失效。下面「复制行」那条就是这么暴露出来的。

**书里的清单是我用自己的话复述的**，没拿到逐字原文（O'Reilly 是付费墙）。搜索结果与记忆一致，但**逐条措辞不保证准确**，需要精确引用时请翻实体书 Topic 18。

## 书里点名的能力

《程序员修炼之道》20 周年版 Topic 18 的主张是：文本是编程的原材料，编辑器该像手的延伸，这些操作都不该靠鼠标和菜单。它点名的大致是：

| # | 能力 |
|---|---|
| 1 | 按字符、词、行、段落移动和选择 |
| 2 | 按**语法单位**移动（匹配的括号、函数、模块） |
| 3 | 改动后重新缩进 |
| 4 | 一条命令注释 / 取消注释代码块 |
| 5 | 撤销与重做 |
| 6 | 分屏成多个面板并在面板间跳转 |
| 7 | 跳到指定行号 |
| 8 | 对选中的行排序 |
| 9 | 搜索字符串与正则，并重复上次搜索 |
| 10 | 基于选区或模式匹配临时开**多光标**，并行编辑 |
| 11 | 查看当前项目的编译错误 |
| 12 | 运行当前项目的测试 |

值得注意的是这份清单的**重心**：12 条里只有第 1 条属于「移动与选择」——也就是我们目前在 Hyper 层做得最重的那块。其余 11 条是**结构操作**和**工具链动作**。

## 查出来的问题

### 1. 复制行可能真的没键位了 ⚠️

改 Zed 时我把 `⌥⇧↑↓` 从 `DuplicateLine` 拿走给了 `MoveLine`，当时说「复制行不会失去入口，Zed 默认 `⌘⇧D` 就是」——**那句话是错的**。

`cmd-shift-d → DuplicateLineDown` 位于**数组 #10，JetBrains 兼容层**。你的 `base_keymap` 是 VSCode，那一层根本没加载。

现存的唯一候选是 VSCode 层的 `⌘D → editor::DuplicateSelection`。**它在空选区时复不复制整行，需要实按确认。** 不行的话得补一个绑定。

### 2. 书里 12 条能力，Hyper 层只覆盖了第 1 条

`⇪⌘N`（删整行）、`⇪⌘M`（删到行首）、`⇪⌥U/P`（移动行）属于 B 区，也没被书点名。**C 区（结构与工具链）Hyper 层是全空的**——而那是书的重心。

这不一定是缺陷：C 区的操作大多已经是**单个 `⌘` 组合**（`⌘/`、`⌘Z`、`⌘L`、`⌘B`），手不用离开主键区多远，Hyper 化收益有限。真正值得考虑的是需要**双组合键或方向键**的那几个：多光标 `⌘⌥↑↓`、分屏 `⌘K ←`、折叠 `⌘K ⌘L`。

### 3. 书里点名而你完全没有的三条

| 能力 | 现状 |
|---|---|
| **排序选中行**（#8） | Zed 里连键位都没有，动作是 `editor::SortLinesCaseSensitive` |
| **跳到匹配括号**（#2） | `⌃M` 有绑定，但从没用过 |
| **缩进 / 反缩进**（#3） | 没查到独立绑定（`⌘⌥L` 是整体格式化，不是手动缩进） |

### 4. keystat 给的反直觉事实

```
⇪H / ⇪L  左右移   87 / 90 次   ← 最高频
⇪K / ⇪J  上下移   0 次
```

**单行垂直移动一次都没按过。** 垂直方向你走的是 `⇪⌥J/K`（三行，28+14）和翻页。水平要精确到字符，垂直精确到单行没意义——看得见就直接跳。
